# R5-A 未实现功能与局限

## 未实现

- Halo2 / Rust / Noir 电路；本仓库没有任何 ZKP 实现。
- 真实发行者签名与签名验证；`issuer_id` 仅为标签。
- 分布式 CAS、共识、多节点线性一致性、跨存储原子性、exactly-once。
- 持久化存储、崩溃恢复、并发控制。
- 真实业务授权策略；`Φ` 是为实验冻结的人造不变量。
- 对 SMT 键哈希碰撞的实际防护（仅依赖 SHA-256 抗碰撞性假设）。
- **完整集合证明**：`verify_leaf_set_consistency()` 需要枚举全部叶证明，且只检查「所给集合」的聚合，
  不能证明没有遗漏的叶。R5-A-R2 增加了重复 key / 重复路径标识防护，但 T16-E 演示遗漏 tombstone
  仍会通过；它不是 ZK 证明。
- **真正的状态转换证明**：`verify_transition()` 只检查旧根/新根和三个版本字段与外部可信检查点一致、
  version 递增 1，不验证 `S_{t+1} = Transition(S_t, e_t)`，也不验证事件合法性与聚合更新正确性。
- **检查点认证**：`TrustedCheckpoint` 只是外部输入的数据结构；本原型不验证其来源、签名或透明日志证据。

## 局限

- 性能数据来自单进程 CPython 原型，未做优化；不得外推为生产系统性能。
- 增量聚合摘要与独立全量 Oracle 是两条独立代码路径，但都在同一进程、同一语言实现；不一致检测依赖测试覆盖，而非形式化证明。
- 失败操作的「状态不变」由实现中的先校验后提交顺序保证，并由测试验证；不代表数据库事务级原子性。
- 非成员证明基于「键哈希对应叶为空」，不处理哈希碰撞情形。
- Gateway 不执行外部动作，因此不产生任何真实世界副作用证据。
- 原始性能口径（R5-A）只计时 `recompute_aggregate(active_grants)`，没有重建 SMT/全局根，
  因此不能据此宣称「增量完整状态更新优于全量完整重建」。R5-A-R1 增加了端到端全量重建基线，
  但基线只含 seed 授权、与增量操作后的状态不同。**R5-A-R2** 改为每个正式样本独立初始化，
  分别从 REGISTER 后与 REVOKE 后的实际状态（含 tombstone）从空树全量重建并断言根相等；
  比值仍是同一未优化 CPython 进程内的一次操作对照，不是 ZKP 证明成本或生产系统加速比。

## 研究价值判定边界

本仓库只能回答：

1. 增量聚合摘要是否与全量集合重算一致；
2. 双层 SMT 路径与承诺能否被独立验证；
3. 攻击测试与随机测试是否在指定规模内保持不变量。

本仓库 **不能** 回答：

- 是否值得进入 Halo2 阶段（需要额外论证「相对已有机制的增量价值」）；
- 是否具备零知识安全性；
- 是否可在真实多 Agent 系统中替代现有机制。
