# R5-A 威胁假设与安全边界

## 假设

1. **哈希假设**：SHA-256 的抗碰撞性在本实验中被当作给定前提。原型不证明该假设。
2. **攻击者控制输入**：调用方可以提供畸形 `Grant`、伪造 `expected_version`、伪造证明字节域（兄弟路径、聚合摘要、内层根、外层根）。
3. **攻击者不直接修改 Registry 内部字典**：但独立验证器必须把收到的证明字节视为不可信，并在 T5 / T16 / T17 中实际篡改后验证其拒绝能力。
4. **单进程**：所有更新在一个 Python 进程内顺序发生；没有并发写者、没有网络分区、没有拜占庭节点。
6. **可信检查点由外部提供**：验证者必须从信任来源取得 `TrustedCheckpoint(root, version)`；本原型不实现检查点签名、透明日志或共识。调用方自造的 checkpoint 不是可信事实。
5. **策略为人为设定**：`Φ(Q) = (n_E=0 ∨ n_D=0) ∧ (B≤100)` 是可判断的测试不变量，不对应真实业务授权规则。

## 明确不假设 / 不实现

- 不实现发行者签名。`issuer_id` 不是签名验证结果，不能据此声称身份真实性。
- 不实现零知识证明、Halo2 电路、Rust 或 Noir。
- 不实现分布式共识、多节点线性一致性、跨存储原子性或 exactly-once。
- 不实现检查点认证、透明日志或检查点来源的可信链；`TrustedCheckpoint` 的「可信」是外部前提，不是本原型的性质。
- 不声称信息隐藏、隐藏性（hiding）或见证不可知（witness indistinguishability）。
- 不声称本原型具有任何形式化安全证明。

## 验证器边界

独立验证器检查的是 **哈希承诺与路径一致性**：

- SMT membership / non-membership 路径；
- 内层根与外层根；
- Agent 状态叶中的聚合摘要承诺；
- 旧根、新根与三个版本字段同时绑定可信检查点（R5-A-R2 / T17）；
- 叶集合中的重复 key 与重复 SHA-256 路径标识（R5-A-R2 / T16）；
- tombstone 与 ACTIVE 记录的区分。

它 **不是** 电路证明，也 **不是** 零知识证明。任何验证成功只说明「给定根下，这些字节与路径自洽」。

R5-A-R1 / R2 明确边界：

- `verify_leaf_set_consistency()` 可检查「所给叶集合的 ACTIVE 聚合 == 承诺摘要」，并拒绝重复 key /
  重复路径标识，但需要枚举全部叶，**不证明没有遗漏的叶**（T16-E 演示：遗漏 tombstone 仍会通过）；
  不扫描全部叶的一致性验证 **未实现**。
- `verify_transition()` 是外部可信检查点一致性检查，**不证明** `S_{t+1} = Transition(S_t, e_t)`。
- 检查点绑定不是检查点认证：它只保证证明与给定检查点一致，不保证检查点本身可信。
